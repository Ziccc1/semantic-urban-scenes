# 三维语义城市场景生成｜平台接入规范 v1 建议版

## 1. 接入边界与责任

平台读取离线样例包。各方法负责人负责推理、保存原始结果和导出，平台负责人负责校验与渲染。首次联调冻结字段后再批量交付。目录内引用使用相对路径，示例数据与原生数据均可从清单定位。

## 2. 每个样例包的 manifest.json

| 字段 | 类型 | 规定 |
|---|---|---|
| schema_version | 字符串 | 第一版为 "1.0" |
| method | 枚举 | scene_scale_diffusion、pdd、semcity、pritti |
| sample_id | 字符串 | 同一方法内唯一，所有日志沿用 |
| task | 枚举 | generation、reconstruction、completion、inpainting、extension、object_edit |
| provenance | 对象 | 至少含 dataset、code_version、weights、config_path、log_path；权重写名称或来源 |
| labels | 数组 | 每项含整数 id、name、color（#RRGGBB）、role（semantic、empty 或 unknown）。标签用本方法实际映射 |
| states | 数组 | 每个状态含唯一 id、role、format、path；按展示顺序排列。role 用 input、condition、output、coarse、medium、fine、before、first_output、adopted 或 ground_truth |
| regions | 数组，可选 | 每项含 id、state_id、role、min_xyz、max_xyz。角色可用 mask、window、overlap、protected 或 issue |
| experiment | 对象，可选 | PrITTI 专项样例引用 steps.json 和评价记录 |

## 3. 两种展示数据

| format | 适用 | 展示文件与必要字段 |
|---|---|---|
| voxel_points_json | Scene-Scale Diffusion、PDD、SemCity | JSON 对象含 voxel_size_xyz、points，每个点为 [x,y,z,label_id]，坐标是体素中心；默认仅导出需要展示的占据体素。清单中保留原生数组路径与原生轴顺序、标签和分辨率说明。 |
| ground_objects_json | PrITTI | JSON 对象含 ground 和 objects。ground 使用稀疏有效格列表 cells，每项为 [x,y,z,label_id]，并提供 cell_size_xy；objects 每项含 id、label_id、shape（box 或 ellipsoid）、center_xyz、size_xyz、yaw_rad。size_xyz 是完整尺寸，角度绕 +Z，按右手规则。 |

展示数据统一使用米、右手系、+Z 向上，导出者对同一样例的输入输出使用共同场景坐标。支持多尺度的状态分别保存各自格尺寸。展示文件应保留与原生输出的对应关系，包含转换说明；对无法表示的对象属性保留原生文件。区域边界框用于定位，像素级或体素级掩码另附原生文件和轴顺序、形状、取值说明。

## 4. 四种方法最少交付状态

| 方法 | 平台必交 | 验收动作 |
|---|---|---|
| Scene-Scale Diffusion | 无条件生成的 output | 能看三维和俯视，核对道路和对象标签。若展示补全，加 condition、output、ground_truth。 |
| PDD | coarse；其余已跑通尺度各交一个状态 | 按已交付尺度切换并检查位置、比例和标签一致。 |
| SemCity | 代表区域操作的 condition、output，附操作区域记录 | 同视角对照操作前后，定位掩码或扩展窗口。 |
| PrITTI | 单次扩展的 before 和 adopted；专项加 first_output | 显示地面与物体，定位重叠区，查看首次生成与采用结果。 |

## 5. PrITTI 专项记录接口

steps.json 为记录数组。每行包含 run_id、sample_id、strategy（A/B/C）、step（首个扩展步编号 1）、parent_state_id、first_state_id、adopted_state_id、window_region_id，以及 issue_region_ids。所有引用须指向相应样例包中存在的状态或区域。另记录 action（none、resample、local_repair）、status（success、failed 或 skipped）、attempts 和 elapsed_ms。每次 attempt 记录 seed、elapsed_ms、status 和输出路径。输出或状态因失败无法产生时，在记录中使用 null，并写明后续是否终止或沿用可用状态。

评价表由 PDD 负责人交付，使用 run_id、sample_id、strategy、step 与步骤记录匹配。每条写明问题类别、区域编号、道路/地面/保留区度量及单位、是否人工复核。n/a 和缺失数值用 null 并注明原因。平台状态切换到哪一步，就显示该步当前策略的区域、修正前后和运行开销。

## 6. 最小清单示例

~~~json
{
  "schema_version": "1.0",
  "method": "pdd",
  "sample_id": "carla-001",
  "task": "generation",
  "provenance": {
    "dataset": "CarlaSC",
    "code_version": "<commit>",
    "weights": "<coarse-checkpoint>",
    "config_path": "source/config.yaml",
    "log_path": "source/run.log"
  },
  "labels": [
    {"id": 1, "name": "road", "color": "#606774", "role": "semantic"}
  ],
  "states": [
    {
      "id": "coarse-1",
      "role": "coarse",
      "format": "voxel_points_json",
      "path": "display/coarse.json",
      "native_path": "source/coarse.npy"
    }
  ]
}
~~~

例中的标签、路径和版本均需换成实际值。正式交付补齐从原生坐标到展示坐标的转换说明及展示文件中引用的全部标签。

## 7. 首轮验收

1. PDD 负责人交已有粗尺度样例。平台负责人确认断网可读、尺度正确、标签能查，确认第一种读取格式。
2. PrITTI 负责人交扩展前后状态。PDD 负责人提供一条问题位置，平台负责人核对同一位置在俯视、三维与实验记录中一致。
3. Scene-Scale Diffusion 和 SemCity 负责人各交一包。检查 manifest、文件引用、状态切换、颜色、单位及原生数据回查。
4. 四种样例通过后冻结 v1。变更字段含义或坐标约定时更新版本，提供者和接收人用一个样例重新核对。
