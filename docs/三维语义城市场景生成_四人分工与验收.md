# 三维语义城市场景生成｜四人分工与验收

## 四人各自负责一个方法

| 岗位（待认领） | 必做复现 | 有条件再做 | 技术交付 |
|---|---|---|---|
| Scene-Scale Diffusion | 用 CarlaSC 跑通公开权重的无条件生成。固定采样设置，记录至少一个种子，保存语义体素和俯视图，检查道路布局和类别分布。 | 有对应稀疏观测和真值时，做条件补全，保存观测、预测、真值，明确评估范围后计算占据 IoU 和语义 mIoU。 | 环境与运行命令、权重和配置、原生体素、一个平台样例。 |
| PDD | 接续已有粗尺度结果，在 CarlaSC 上验证粗到细的尺度传递。按实际跑通的尺度分别保存输入、输出和同视角图，观察结构保留与细节变化。 | 能运行重叠子块生成时，交一例高分辨率接缝对照。后续尺度受阻时提交粗尺度代表样例和阻塞日志。 | 各可用尺度的配置与原生输出、尺度对照图、一个含尺度状态的平台样例。 |
| SemCity | 用适配公开权重的数据跑通基础生成，再从局部重生成和单次扩展中选一项验证。记录条件场景、操作范围和输出，检查衔接与保留区域。 | 补全细化或第二种区域操作视进度开展。使用 CarlaSC 或 SemanticKITTI 时记录实际数据版本和标签映射。 | 环境与运行命令、输入/输出/掩码、一个平台样例。 |
| PrITTI | 用 KITTI-360 跑通布局生成和单次扩展，验证局部掩码是否可调用。保存地面类别、高度、有效区和物体位置、尺寸、朝向。 | 用同一布局验证基元编辑及保存重载，作为可选平台演示。 | 单次扩展前后原生状态、坐标与窗口说明、配置日志、一个平台样例，以及专项实验的生成程序。 |

每人负责本方法从环境、推理到导出与结果说明。建议复现范围以公开权重和代表功能为主。报告分别登记已跑通、失败和待验证的功能。

## 两项组内公共工作

- **平台**建议由 SemCity 负责人牵头，先用已有 PDD 结果实现离线浏览。四位方法负责人各写或维护自己的导出脚本，各交一个可读取的样例。平台负责人维护清单校验、体素与地面/物体读取、三维与俯视、状态切换和问题定位。平台按[接入规范](三维语义城市场景生成_平台接入规范.md)读取预先生成的结果。
- **优化专项**由 PrITTI 负责人主做扩展和掩码修正，PDD 负责人主做道路衔接、地面高度跳变、保留区变化检查，Scene-Scale Diffusion 负责人参与人工复核与材料汇总。用同一初始街区、权重、方向和主要采样设置比较 A 直接扩展、B 整个新增街区重采样、C 局部修正。B/C 共用触发与重试规则，记录随机种子、运行耗时及额外调用量。先交一组完整对照。

## 并行与交接

| 时点 | 可并行任务 | 必须交付后才能推进的工作 |
|---|---|---|
| 开始 | 四种模型各自试跑，PDD 负责人用测试网格做检查，平台用已有 PDD 样例或测试数据开发 | PDD 负责人先交一个样例包给平台负责人，双方核对标签、轴向与比例，再确认接入格式。 |
| PrITTI 单次扩展跑通 | 各方法继续验证代表功能，平台逐个验收已到达样例 | PrITTI 负责人交扩展前、首次扩展后状态及坐标、窗口、重叠区和保留区给 PDD 负责人。PDD 负责人完成真实样例检查，交回异常位置和建议掩码范围。 |
| 专项联调完成 | 不同样本或同一样本的三种策略可在独立运行目录同时执行。平台按批导入结果。 | PrITTI 负责人和 PDD 负责人共同确认掩码映射、触发规则、重试上限及失败处理。同一样本同一策略必须逐步执行，每步最终状态才是下一步输入。 |
| 提交前 | 四位负责人各写一段复现结果与局限 | PrITTI 负责人交逐步状态和调用日志，PDD 负责人交评价表，平台负责人接入同一组结果，Scene-Scale Diffusion 负责人核对报告、图表与案例编号。 |

## 四、各方法的执行与验收清单

### 1. Scene-Scale Diffusion 负责人

- [ ] 确认 CarlaSC 数据路径、标签映射、输入张量形状、空闲与未知标签。记录代码版本、权重文件、环境和实际运行命令。
- [ ] 用一个种子跑通无条件推理，核对原生输出能解码成语义体素，检查场景尺寸、有效标签和空闲区域。保存运行配置、种子、耗时和原生体素。
- [ ] 固定采样设置，另选一个种子生成样例。用相同类别配色和观察角度出图，简要描述道路结构、类别分布和样本差异。
- [ ] 条件补全作为扩展任务。具备匹配观测和标注时，保存稀疏输入、预测、真值，明确评价区域和忽略标签，再计算占据 IoU 与语义 mIoU。
- [ ] 按接入规范导出至少一个体素展示包，交平台负责人核对轴向、色表与俯视效果。撰写本方法的复现结果、配置和局限。
- [ ] 公共任务是复核 PDD 负责人提交的 PrITTI 疑似异常，注明确认、排除或待议及依据。收齐四人的技术小节与案例编号，核对报告、PPT 和平台展示。

### 2. PDD 负责人

- [ ] 接收已有粗尺度样例及其运行条件，核对输入、权重和输出形状。用原配置复跑一次，保存日志和粗尺度输出。
- [ ] 按粗、中、高顺序验证尺度传递。逐级记录输入条件、权重、分辨率、运行状态和生成结果。每个跑通尺度保存同方向俯视图，说明整体布局保留与局部细节变化。
- [ ] 高分辨率子块可用时，保存相邻块、重叠区及融合后结果，检查道路或类别是否在边界错位。若卡在某一级，记录已完成尺度、失败环节与对应日志。
- [ ] 优先把现有粗尺度样例转成交付包，交平台负责人验证第一种读取方式。后续在同一样例的清单中补充可对照的尺度状态。
- [ ] 公共任务是 PrITTI 评价。先用小网格准备道路断开、地面跳变、保留区改动三类测试，再接收真实扩展状态核实检查范围和坐标。交出异常类型、位置、修正建议范围与复核判断。
- [ ] 专项跑完后按样本、方案、步号汇总接缝现象、保留区变化、耗时和调用次数。提交至少一组可回查的前后对照，撰写评价方法和结果。

### 3. SemCity 负责人

- [ ] 选定与公开权重匹配的数据集，记录实际版本、类别、空间分辨率、权重和运行入口。跑通基础生成，保存原生语义输出。
- [ ] 优先做一项区域操作。做局部重生成时保存初始场景、掩码和输出；做单次扩展时保存条件区、窗口和输出。用同视角图检查操作边界与固定区域变化，补全细化视进度安排。
- [ ] 导出至少一个带条件、输出和区域标记的 SemCity 样例包，撰写代表功能与复现限制。
- [ ] 公共任务是平台。先用 PDD 测试样例实现离线加载、三维旋转缩放、俯视和类别配色。依次接入其余模型，逐包检查清单、文件引用、坐标方向、比例和配色。
- [ ] 对 PrITTI 接入地面与物体两种数据，支持选择样本、A/B/C 方案和扩展步，显示问题标记、修正前后和开销。用一组真实对照核对同一个问题在俯视、三维与评价表中的位置。
- [ ] 交本地启动说明、可离线运行的样例目录、演示顺序和截图。上台前在展示电脑断网试运行，各方法负责人核对自己的场景。

### 4. PrITTI 负责人

- [ ] 接续 KITTI-360 的标注处理，确认代码、权重、初始布局输入与坐标，保存可复跑的命令及配置。
- [ ] 完成一次布局生成和一次空间扩展。保存扩展前、首次扩展后和最终采用状态，包含地面类别、高度、有效区、物体位置、尺寸及朝向。交出窗口、重叠区、保留区与坐标转换说明。
- [ ] 验证局部重生成。将 PDD 负责人提供的问题范围映射到当前生成窗口，核对掩码形状、方向和值的含义，保存合并后的状态，检查固定区变化。
- [ ] 实现 A 直接扩展、B 整个新增区重采样、C 局部修正。与 PDD 负责人用首个样例确认触发、重试上限和失败处理。冻结配置后，优先从同一初始街区跑完一组多步对照。
- [ ] 按方案与步骤保存首轮输出、采用状态、掩码和每次尝试日志，记录随机种子、耗时、调用次数与失败状态。下一步明确引用上一轮最终采用状态。
- [ ] 交专项样例包给平台负责人、交原生状态和日志给 PDD 负责人。撰写生成流程、修正策略与失败案例。具备时间时再验证基元编辑与重载。

## 五、公共任务的逐项交接

| 顺序 | 交付人 → 接收人 | 交付物 | 接收验收 |
|---|---|---|---|
| 1 | PDD → SemCity | 已有粗尺度体素、标签、坐标说明及第一版清单 | 能离线加载，俯视方向和类别颜色正确。其他方法可同步推理。 |
| 2 | PrITTI → PDD、SemCity | 单次扩展前后状态、窗口、重叠与保留区、单位与变换 | PDD 能锁定检查边界，SemCity 能显示同坐标的地面和物体。 |
| 3 | PDD → Scene-Scale Diffusion → PDD | 疑似异常编号、截图、范围与独立复核意见 | PDD 汇总争议与最终判定，并记录依据。 |
| 4 | PDD → PrITTI | 已确认异常和建议修正范围 | PrITTI 生成实际掩码并返还修正前后状态，PDD 核对处理范围。 |
| 5 | PrITTI、PDD → SemCity、Scene-Scale Diffusion | 同一组 A/B/C 逐步场景、标记、配置、评价和耗时记录 | 平台能逐步对照，汇总者能按编号查回原始状态与日志。 |
| 6 | 四人 → Scene-Scale Diffusion、SemCity | 每人一份功能结果、局限、代表样例编号和贡献说明 | 汇报稿中的图表与平台可打开的样例一一对应。 |

首轮优先完成第 1、2 项。其他模型试跑、检查脚本和平台骨架均可并行。正式专项的第 4 项必须在第 2 项后验证，规则冻结后再批量运行；不同策略或样本可独立执行，同一条序列逐步推进。
