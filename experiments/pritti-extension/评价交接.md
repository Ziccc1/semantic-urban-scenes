# PrITTI 逐步评价交接

入口 `evaluate_steps.py` 按 `run_id`、`sample_id`、`strategy`、`step` 对齐 PrITTI 的 `steps.json`，分别检查首次生成和最终采用状态。输出道路匹配、高差、保留地面变化、异常米制坐标、建议修正范围和日志开销。评价只读生成结果。[输入格式与评价协议](PrITTI评价协议.md)

## 真实样例接收清单

- 同起点的一组 A/B/C 记录，含 `manifest.json`、`steps.json`、原生状态与耗时、调用日志。
- 首个真实窗口的坐标变换、接缝位置、重叠区、实际保留区掩码及标签定义。双方核对异常建议范围和实际掩码。
- 同视角前后图供复核，并记录异常的确认、排除或待议。物体保护检查需要稳定 ID。

本地已用人工 `4×3` 栅格复核三类异常、A/B/C 逐步对照和跳过状态。可运行 `smoke_evaluation.py` 重建测试。真实数据到位后执行同一评价入口并记录人工复核。
